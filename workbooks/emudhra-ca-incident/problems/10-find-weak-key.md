## The problem

Write a program that reads public keys and, for each one, finds out whether its private key is a
small number `d` or the curve's order minus a small number, `n - d`.

### How a public key relates to its private key

An elliptic curve is a set of points (x, y) with arithmetic mod a prime `p`. Each curve comes
with a fixed point `G`, the generator. A private key is a whole number `d`, and the
matching public key is the point

```
Q = d * G = G + G + ... + G        (d copies of G)
```

Going from `d` to `Q` is cheap. Cryptographers believe that going from `Q` back to `d` is
infeasible when `d` is a random number of 256 or 384 bits, because there are about 2^256 or
2^384 candidates. If `d` is small, there are few candidates, and an attacker can try them in
order: compute `1*G`, `2*G`, `3*G` and so on until one equals `Q`. In this assignment you carry
out that attack, and the same walk also catches `n - d` (see "The negated key" below).

A tiny example, on the curve `y² = x³ + 2x + 2` mod 17 with `G = (5, 1)` (the `TOY` curve in your
`ecc/curves.py`):

| d | d·G |
|---|---|
| 1 | (5, 1) |
| 2 | (6, 3) |
| 3 | (10, 6) |
| 4 | (3, 1) |
| 5 | (9, 16) |

Given the public key `Q = (3, 1)`, you walk down the table and stop at the row with `d = 4`.

### The arithmetic you need

Your `add_points` from assignment 02 already does the steps below.

Both curves in the tests have the form `y² = x³ + a·x + b (mod p)` with `a = p - 3`. Every
operation below is mod `p`. To divide by `k`, multiply by `k` to the power -1 mod `p`, the
modular inverse (your `modinv` from assignment 01; Python also has `pow(k, -1, p)`).

To add two different points `P = (x1, y1)` and `R = (x2, y2)`:

```
slope = (y2 - y1) / (x2 - x1)
x3    = slope² - x1 - x2
y3    = slope * (x1 - x3) - y1
```

To add a point to itself (`P + P`, called doubling), the slope comes from the curve's tangent:

```
slope = (3·x1² + a) / (2·y1)
x3    = slope² - 2·x1
y3    = slope * (x1 - x3) - y1
```

`d*G` is `(d-1)*G + G`, so each step from one multiple to the next is one addition of `G`. The
first step, from `1*G` to `2*G`, is a doubling, because both points are `G`. The ordinary
formula would divide by `x2 - x1 = 0` there.

### The negated key

The negation of a point is the same x with the other y: `-(x, y) = (x, p - y)`. Let `n` be the
number of points in the group generated by `G` (about 2^256 for P-256 and 2^384 for P-384). Then
`n*G` is the identity, so `(n - d)*G = -(d*G)`. The private key `n - d` is a 256-bit or 384-bit
number, and its public key is the public key of `d` with y flipped.

On the toy curve, `G` generates 19 points (`n = 19`), and `p = 17`:

| d | d·G | -(d·G) = (19 - d)·G |
|---|---|---|
| 1 | (5, 1) | (5, 16) |
| 2 | (6, 3) | (6, 14) |
| 3 | (10, 6) | (10, 11) |
| 4 | (3, 1) | (3, 16) |
| 5 | (9, 16) | (9, 1) |

Given `Q = (3, 16)`, no row of the middle column matches, but `-Q = (3, 1)` is the row with
`d = 4`. That makes `Q = -(4*G)`, and its private key `19 - 4 = 15`.

An attacker gets these keys from the same walk. Compute `-Q = (x, p - y)` once before the loop,
then compare each multiple `k*G` with both `Q` and `-Q`. That costs one subtraction and a second
comparison per step, and no extra point additions. Comparing x first and then looking at y gives
the same answer: a point and its negation are the only two points on the curve with that x, and
every key in the input is on its curve.

Your program reports such a key as `-d`, a minus sign followed by `d` in decimal. That is the
private key `n - d` written mod `n`, since `-d ≡ n - d (mod n)`.

A key can't match both ways. `d*G = -(d'*G)` would need `d + d' = n`, and both values are at most
the bound, which is at most 1000, far below `n / 2`. If both ever applied, the positive form
`d` would win.

### Input

The checker runs your program from the workbook folder as `<program> <input-file> <output-file>`.
The input file contains two kinds of lines:

| Line | Meaning |
|---|---|
| `bound <N>` | The largest `d` to try, for `d*G` and for `-(d*G)`. It applies to every `key` line after it, until the next `bound` line. |
| `key <label> <curve> <x> <y>` | A public key. `label` is a word with no spaces. `curve` is `P-256` or `P-384`. `x` and `y` are lowercase hexadecimal with no `0x` prefix. |

Every key is a valid point on its curve.

### Output

For each `key` line, in input order, write one line:

```
weak <label> <d>      the key equals d*G for a whole number d from 1 to the bound; <d> is written in decimal
weak <label> -<d>     the key equals -(d*G) for such a d, so the private key is n - d; a minus sign, then d in decimal
none <label>          no d from 1 to the bound gives this key or its negation
```

Copy `<label>` from the input unchanged. The checker ignores extra whitespace.

## Requirements

Each test checks one of these requirements. If tests fail, the checker's report shows how many
pass for each requirement, and it may add a `likely cause` line that names the requirement the
difference points to.

- **R1** One output line per `key` line, in input order, in the format above. A later `bound`
  line replaces the earlier one for the keys after it.
- **R2** A key whose `d` lies between 1 and the bound gives `weak` with that `d`. This includes
  `d = 1` (`Q` is `G`), `d = 2` (the first step is a doubling) and `d` equal to the bound.
- **R3** Only `d` from 1 to the bound counts, in either sign. The bound is inclusive, so
  `(bound + 1)*G` and `-((bound + 1)*G)` give `none`, and so does every key whose private key
  is neither `d` nor `n - d` for such a `d`.
- **R4** Both curves work. P-256 and P-384 have their own `p` and `G`.
- **R5** A bound of 1000 with several keys finishes inside the time limit, including keys that
  are not weak, for which every step up to the bound runs.
- **R6** A key equal to `-(d*G)`, the point `(x, p - y)`, with `d` from 1 to the bound gives
  `weak <label> -<d>`. Its private key is `n - d`. This includes `-G` (`d = 1`), `-(2*G)` and
  `d` equal to the bound.

### Example 1: the first step is a doubling (test `10-R2-d2-p256`)

```

         key two P-256 7cf27b188d034f7e8a52380304b51ac3c08969e277f21b35a60b48fc47669978 07775510db8ed040293d9ac69f7430dbba7dade63ce982299e04b79d227873d1
```

`1*G` is `G` itself, with x = `6b17d1f2…`. Your loop compares it with the key (no match), then
adds `G` to get `2*G`. That addition is `G + G`, so it takes the doubling formula. The result
has x = `7cf27b18…`, which matches the key, so `d = 2`.

## Hints

<details><summary>Hint 1: where to start</summary>

A public key is `d` copies of `G` added together, so when `d` is at most the bound you can try
`d = 1, 2, 3, ...` and stop when the point matches the key or the key's negation. Your
`add_points` from assignment 02 does the point arithmetic.
</details>

<details><summary>Hint 2: the approach</summary>

Before the loop, compute the key's negation `(x, p - y)`. Keep one variable for the current
point, starting at `G` (which is `1*G`). In each step, compare it with the key; if it matches,
you know `d`. Then compare it with the negation; if that matches, the answer is `-d`. Otherwise
add `G` to it and move on to the next `d`. One addition per step costs far less than computing
each `d*G` from scratch with `scalar_multiply`. Your `add_points` picks the doubling formula when
both points are the same.
</details>

<details><summary>Hint 3: the traps</summary>

- `G + G` needs the doubling formula; the ordinary formula divides by zero. An `add_points` that
  passed assignment 02 handles this.
- Compare both x and y. A key and its negation share x, and only y tells `d` from `-d`.
- Write `-d` with a minus sign. Printing `n - d` in decimal gives a number of 78 or 116 digits
  where the checker expects `-42`.
- The bound is inclusive and covers both signs: the search finds `d = bound` and `-bound`, and
  neither `bound + 1` nor `-(bound + 1)`.
- Count from 1. `d = 0` is not a key.
- Each `key` line uses its own curve's `p` and `G`, which `CURVES` finds by the curve's name.
- A `bound` line applies to the `key` lines after it, and a later one replaces it.
- Coordinates are hex text. Parse them as base 16, and print `d` in decimal.
</details>

<details><summary>Hint 4: pseudocode</summary>

```
add(P, R):
    if P == R: slope = (3*P.x² + a) * inverse(2*P.y)  mod p
    else:      slope = (R.y - P.y) * inverse(R.x - P.x)  mod p
    x3 = slope² - P.x - R.x  mod p
    y3 = slope * (P.x - x3) - P.y  mod p
    return (x3, y3)

find_private_key(curve, Q, bound):
    minus_Q = (Q.x, p - Q.y)
    point = G
    for d from 1 to bound:
        if point == Q:       return d
        if point == minus_Q: return -d
        point = add(point, G)
    return none
```
</details>
